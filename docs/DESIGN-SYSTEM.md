# 聆云 设计规范（Design System）

> 版本：v1.0 ｜ 制定：2026-09-24 ｜ 基调：**杂志感 · 封面为王**
>
> 本文件是全应用统一重构的唯一依据。任何页面改版先看这里，不在页面里凭感觉写颜色和字号。

---

## 0. 四条原则

1. **封面是主角，界面是画框。** 封面占据视觉重心的绝对多数；UI 元素退到背景，不与应用内容争注意力。
2. **留白是设计的一部分，不是没内容。** 宁可少放一个元素，也不要填满。呼吸感来自间距节奏，不来自分割线。
3. **色彩退后，只在需要指示时出现。** 大面积中性色（纸张白 / 墨黑），主色只用于「可点」与「当前选中」。**禁止大面积渐变。**
4. **字阶克制。** 只用 5 级字号、2 种字重（400 / 500）。靠字号与颜色对比建立层级，不靠加粗和描边。

## 1. 色彩

### 1.1 界面中性阶（界面 95% 的面积用这些）

| 用途 | 浅色 | 深色 |
|---|---|---|
| 页面底 | `#FAFAF8`（纸白） | `#141414`（墨底） |
| 卡片面 | `#FFFFFF` | `#1E1E1E` |
| 分隔线 | `#0000001F`（0.5px） | `#FFFFFF1F` |
| 主文字 | `#1A1A1A` | `#EDEDED` |
| 次文字 | `#5C5C5C` | `#A0A0A0` |
| 弱文字 | `#6F6F6F` | `#8C8C8C` |

> 注意：现用的紫色渐变页底（`#F3F0FF → #FBFBFE`）在本次重构中**取消**，改为纯纸白。渐变会让界面显脏，也会和封面色打架。

**99% 的彩色都来自 §1.3 的封面出版色板，不是来自 Material 200 色板。**
`Colors.teal / orange / blue / deepPurple / amber / green` 这类 Material 原色是**高饱和**的，
放在低饱和印刷色的封面旁边像贴了一张塑料标签 —— 这是「廉价感」最直接的来源。
它们的对比度也不可控（`amber.shade700` 在纸白上 3.1:1）。
由 `test/design_system_test.dart` 的「页面里不得出现 Material 原色」守卫锁住
（色值只允许定义在 `lib/theme/` 下）。

### 1.2 主色（只用于可交互与选中态）

- 主色：`#3A3A3A`（墨色）——**按钮、选中态用墨黑，不用彩色**。杂志感的克制来自这里。
- **已落地**（v1.4.0）：`AppTheme.seedColor` 由紫 `#5B4FE9` 改为墨 `#3A3A3A`，进度指示器改走强调色。
  ⚠️ **坑：`ColorScheme.fromSeed` 不能直接吃中性 seed** —— `r=g=b` 时 HCT 的色相未定义，
  M3 会派生出一个**青色** `Color(0xFF006874)` 的 primary，全应用的按钮与选中态集体变青。
  所以 primary / secondary / tertiary / surface / outline / error 必须在 `copyWith` 里**显式指定**，
  由 `test/design_system_test.dart` 用「primary 必须无彩色」这条守卫锁住。
- 强调色（仅用于进度、链接、成功提示）：
  - 浅色 `#1F6F4A`（松绿）
  - **深色 `#52B584`** —— 同一个 `#1F6F4A` 在墨底上只有 **3.01:1**，不达 AA，深色模式必须换更亮的一档
- 警示（仅用于登录失效等需要动作的提示）：`#8A2F22`（砖红）

### 1.3 封面出版色板（8 色，专用于生成封面）

取印刷品的低饱和深色，配米白文字，避免「渐变方块」的廉价感：

| 名称 | 值 | 名称 | 值 |
|---|---|---|---|
| 墨绿 | `#1F3D33` | 绛紫 | `#4A2B45` |
| 砖红 | `#7A2E22` | 铜褐 | `#6B4A32` |
| 藏蓝 | `#1E2A4A` | 松绿 | `#34513F` |
| 赭石 | `#8A5A2B` | 煤灰 | `#2E2E33` |

封面上的文字一律米白 `#F2EDE4`。

**选色规则：必须由书名哈希决定，且哈希算法自己实现（FNV-1a）。** 不要用 `String.hashCode` —— 它在不同 Dart 版本间不保证稳定，会导致升级 App 后同一本书封面换色。

## 2. 字阶（只有 5 级）

| 令牌 | 字号 | 字重 | 行高 | 用途 |
|---|---|---|---|---|
| `display` | 22 | 500 | 1.3 | 页面主标题（「我的书架」） |
| `title` | 17 | 500 | 1.35 | 书名、卡片标题 |
| `body` | 14 | 400 | 1.5 | 正文、章节名 |
| `caption` | 12 | 400 | 1.4 | 作者、来源、元信息 |
| `micro` | 11 | 400 | 1.3 | 角标、标签 |

**只允许 400 与 500 两种字重。** 现有代码里的 `FontWeight.w600` / `bold` 一律下沉到 500。

---

## 3. 间距与圆角

- 间距走 4pt 栅格：`4 / 8 / 12 / 16 / 24 / 32`（沿用现有 `AppSpacing`）。
- **页面左右边距统一 16**；区块之间用 24，区块内元素之间用 8~12。
- 圆角：卡片 `16`、封面 `10`、芯片 `10`、按钮 `14`、头像/胶囊 `999`。
- **卡片不再用描边**（现有 `outlineVariant` 描边在纸白底上显得脏）；改用**无边框 + 极淡投影**区分层级。

## 4. 封面规范（本次重构的核心）

封面比例统一 **3:4 竖版**（书是竖的；现有方形封面是「专辑」语义，不符合听书心智）。

### 4.1 封面来源优先级

```
用户自选封面 (localCoverPath)
  → 网盘/书源自带封面 (coverUrl)
    → 生成封面（本文档 4.2）
```

### 4.2 生成封面版式（三档，越简洁越好）

```
┌────────────────────┐
│ ┌────────────────┐ │  ← 内嵌细线框，米白 25% 透明，距边 8
│ │                │ │
│ │      蛊        │ │  ← 竖排书名，最多 4 字，字号随宽度自适应
│ │      真        │ │     米白 #F2EDE4，字重 500
│ │      人        │ │
│ │                │ │
│ │                │ │
│ │  ──            │ │  ← 一条 24px 短横线，米白 40%
│ │  老宝玉         │ │  ← 作者/来源，micro 级
│ └────────────────┘ │
└────────────────────┘
    底部叠 2px 进度条（仅在有进度时）
```

规则：
- 竖排书名取书名**最前 4 个字**（grapheme 安全，用 `characters`，不能按 `codeUnit` 切，否则 emoji / 生僻字会切碎）。
- 短横线只在有作者信息时出现，避免空装饰。
- 底部进度条：用**强调松绿**，高 2px，贴底边，宽度 = 已听百分比。无进度则不画。
- 生成封面**不需要网络**，因此是「所有书立刻有体面封面」的兜底，永远可用。

### 4.3 封面上的角标

来源角标（夸克 / 百度 / 本地 / 在线）统一放**左上角**，样式：纸白底 80% 透明 + 墨色 `micro` 文字 + 圆角 6，内边距 `4×6`。
**不要**再用彩色角标（v1.5.0 前用的是 teal / orange 等 Material 原色，已换成出版色板）。

### 4.4 封面自动发现 + 生成封面缓存

网盘有声书目录里常常就躺着一张 `cover.jpg` / `folder.jpg`，但书架此前从不去看它。

流程（`CoverAutoFinder` + `BookCoverService`）：

| 阶段 | 行为 |
|---|---|
| 挑选 | 列一遍目录，按文件名挑封面图：`cover / folder / album / poster / front / 封面 / 书封` 完全命中优先，其次取第一张图片（`jpg / png / webp / bmp / gif`） |
| 校验 | 下载后**看文件头**而不是扩展名 —— 网盘鉴权失败时常返回一个 HTML 正文冒充图片 |
| 落盘 | 存到 `<应用文档>/covers/{id}.{ext}`，回写 `BookshelfBook.localCoverPath` |
| 兜底 | 找不到 → 本地离屏渲染生成封面 PNG 存成 `{id}.gen.png`（零网络） |

两条重要约定：

- **必须落盘，不能存 URL**。网盘封面直链**带鉴权且会过期**，存 URL 等于下次启动必然加载失败一次再回落。
- **发现到的封面与生成封面用不同文件名**（`{id}.jpg` vs `{id}.gen.png`）。这样"先生成过"不会挡住以后网盘里出现真封面。
- 一轮处理上限 12 本、并发 2；失败的书记 `cover_probed_{id}`，不每次进书架都重试联网。
- 本地渲染失败（比如没有可用字体）**不算错误**：封面缓存是优化不是功能，必须有 widget 版生成封面兜底。

## 5. 组件规范

### 5.1 `BookCover`（新组件，替代各页面自绘封面）

统一承担「自选图 → 网络图 → 生成封面」三级降级与角标、进度条渲染。**任何页面需要封面都必须用它**，禁止再写 `CachedNetworkImage` 或自绘渐变。

### 5.2 继续收听卡（书架首屏）

- 位置：首屏第一位，滚动时跟随（后续可做吸顶）。
- 内容：封面（小） + 书名(title) + 当前章(body) + 「第 X 章 / 共 Y 章」(caption) + 播放按钮（墨色实心圆）。
- 没有收听记录时**整卡不显示**，不显示空状态占位。

### 5.3 网格卡（书架）

- 两列，封面 3:4，下方书名 1 行截断 + 元信息 1 行。
- 元信息优先级：`第 X/共 Y 章` > `已听 42%` > 来源。**优先显示「还剩/已到哪」，不显示无意义的百分比。**
- 未读的书不显示进度条。

### 5.4 紧凑入口（倍速 / 定时 / 章节）

高度 34，圆角 10，未选 = 透明底 + 0.5 分隔线，选中（已生效）= 墨色底 + 纸白字。
内容为「图标 16 + 间距 5 + 字号 micro」。

同一组入口并排时**等宽铺满**（各占 `Expanded`），不要用内容宽度 + `spaceEvenly` ——
文字长短不一时宽度会参差，读起来不像一组并列选项。

> 历史：曾把倍速与定时展开成整排常驻档位芯片，用户明确反馈**不需要展开**。
> 高频 ≠ 需要常驻，弹窗内选择同样点得很快，而展开会长期占用版面。

### 5.5 顶部栏目导航（取代底部 NavigationBar）

- **刊头**：`聆云` wordmark（`AppType.title` + 字距 3）+ 右侧两个入口：**搜索**、**网盘**。
  两者都是「往书架里加东西 / 在书架里找东西」的跨栏目动作，属于同一层级 ——
  网盘入口曾经只存在于书架的 ⋮ 菜单里，等于把应用的入口藏在一个栏目内部。
- **栏目行**：在听 / 书架 / 历史 / 统计，等宽四格，高 44。
  选中 = 主墨色 + 字重 500 + 16×2px 强调色下划线；未选中 = 次级墨色 + 400。
- **切换有两种输入，互不打架**：点栏目行（离散）与左右滑动 `PageView`（连续）
  共用同一个 `PageController`；下划线由 `onPageChanged` 驱动，不需要两套同步逻辑。
  四个页面套 `KeepAlivePage`，让 PageView 回到 `IndexedStack` 的「全都留着」
  —— 滑去隔壁就把已加载的书与滚动位置丢掉是不可接受的。
- 四个栏目页**自身不带 AppBar**（刊头与栏目行由 HomePage 统一提供，避免页头叠页头）；
  页面级动作（书架的更多菜单、历史的清空）收进页内动作行，右对齐，**高度压到 32px**
  —— 网盘入口上移后它只剩一个「更多」按钮，不值得再给它一行的呼吸空间。
- 为什么导航上移：底部让位给常驻迷你播放条（§5.7）——「接着控制播放」的频率
  不低于切栏目，且拇指够底部的成本最低；杂志的目录逻辑是横向栏目，顶部更贴；
  底部少一层 64px 导航栏，列表首屏多露一行内容。

### 5.6 播放页版式

自上而下固定七段：

| 段 | 规格 |
|---|---|
| 封面 | 3:4 竖版，高度上限为可用高度的 40%，圆角 12，**由 `BookCover` 渲染** |
| 书名 | `AppType.title`，居中，最多 2 行 |
| 副标题 | `AppType.caption` + 次级墨色；`第 N 章 · 章节名　演播者 演播` 合成一行 |
| 时间行 | 左=当前位置，中=**「本章还剩 mm:ss」用强调色**，右=全长；均为 `AppType.micro` + 弱墨色 |
| 进度条 | 3px 轨道 + 11px 滑块，墨色（不用主题紫） |
| 主控件 | 上一章 · **15** · 播放 · **30** · 下一章 |
| 紧凑入口 | 倍速 / 定时 / 章节（等宽，见 §5.4） |

**副标题合成一行**：章节序号与演播者是同一层级的信息，分两行白占一行高度。

**「本章还剩」而不是「已听 N%」**：听书的人靠剩余时长决定「这章还能不能听完再睡」，
百分比对他做不了任何决定。数据源是 `AudioPlayerService.duration`（当前章节时长），
不需要持久化字段。

**±秒跳转是本页新增能力**：中心按钮左右分别是**后退 15 秒**与**前进 30 秒**，
数字比图标更能直接传达幅度。此前没有这个入口，想回听一句只能拖进度条。
目标位置由顶层纯函数 `offsetPosition()` 计算并夹在 `[0, duration]`；
`AudioPlayerService.seek` 自身不钳制，越界值直接下传会让平台行为不一致。

**主控件一行的宽度预算**（窄屏不能溢出）：44 + 46 + 62 + 46 + 44 = 242，
两侧内边距各 20 → 最窄常见机型 320dp 下可用 280，留有余量。
改动这几个数字前先算一遍。

### 5.7 常驻迷你播放条（取代全局悬浮球）

挂在 HomePage 的 `bottomNavigationBar` 槽位，是首页层级的常驻元素：

- **顶边 2px 进度线**（强调色）显示当前章节进度 —— 不占内容高度，进度却一眼可见。
- 内容行：42×56 封面（3:4，`BookCover`）+ 书名（caption/500）+ 章节（micro/弱墨色）
  + 墨色圆形播放/暂停（40px）+ 下一章。信息区点击进播放页。
- **失败态**：章节行换成警示色错误文案（`AppInk.warning` + `error_outline` 图标，
  与 §5.10 错误态同一语义），右侧「下一章」换成「重试」；静默退避重试期间显示
  18px 转圈并隐藏按钮（避免连点）。迷你条是「不在播放页」时唯一能看到播放状态的
  地方 —— 后台连播失败必须在这里可见，而不是让用户以为 App 卡死。
- 无在播的书时整条收起（高度动画到 0），不留空条占位。
- **只在首页层级显示**：进入播放页 / 详情页等推送路由时整个首页被覆盖，
  本条随之隐藏 —— 「在哪显示」由组件树位置决定，不需要
  `PlayerPage.isShown` 这类全局判断（旧悬浮球挂在全局 Overlay 才需要）。
- 旧悬浮球已移除：可拖拽球体与「点开横条」的两段式交互换成了零寻找成本的
  常驻条。推送路由（详情 / 搜索 / 网盘浏览）里没有播放控制入口，
  这些页面自带播放入口或返回首页即可控制，代价可接受。

### 5.8 详情页版式（书架书籍详情）

自上而下：**头部 Hero → 简介（可展开）→ 目录工具行 → 分页条 → 章节行**。

| 段 | 规格 |
|---|---|
| 顶栏 | **不带标题**（只留返回 + 编辑 + 更多）：头部已用 display 字号放了书名，顶栏再来一次是重复噪声 |
| 头部 | 封面 **132×176**（与「在听」主打卡同档）+ 书名 `display` + `演播者 演播` + `N 集 · 来源` + **收听进度（强调色 micro）** |
| 封面 | **可点直接续播** —— 进详情页最常见的目的就是「接着听这本」 |
| 简介 | 默认 4 行，点「展开」看全文（长简介不该挤掉首屏的目录） |
| 目录工具行 | 左「目录 N 集」，右三个图标按钮：正/倒序、定位到当前集、回到顶部 |
| 分页条 | 每页 300 集；无描边芯片，选中 = 墨色实底 |
| 章节行 | 集号右对齐成 30px 一列 + 标题；正在播放 = **左侧 2px 强调色竖条** + 主墨色 500 + 尾部「正在播放」 |

**正在播放的行不铺底色**：长目录里整行底色会连成一片色块；2px 竖条与
§5.7 迷你播放条的进度线是同一种语言，扫一眼就能找到。

**目录工具不再用可拖动的浮动圆钮**：它和已移除的全局悬浮球是同一种反模式 ——
要记住它藏在哪、还要多点一次才展开。工具属于目录，就固定在目录标题那一行。

### 5.9 搜索页版式（一个入口搜全部）

自上而下：**顶栏搜索框 → 范围三段 → 保存位置行（按范围显隐）→ 结果分区**。

| 段 | 规格 |
|---|---|
| 顶栏 | **搜索框本身占据标题位**（左放大镜图标、无边框、`title` 字号）；右「清空 / 搜索 / 书源管理」 |
| 范围 | 三段等宽胶囊：**本地 / 网盘 / 在线**；选中 = 墨色实底 + `onSolid` + w500，未选 = 透明 + hairline |
| 结果分区 | 书架 / 我的网盘 / 网盘分享 / 在线听书，各带 icon + 标题 + 条数，点标题行可收起 |
| 二级标题 | 在线结果按书源分组：**3px 次级墨色竖条** + 书源名 + 条数 |
| 书架命中行 | **36×48 BookCover** + 书名 `title` + `N 集`（命中就是命中，别再用书本图标顶替封面） |
| 网盘命中行 | 文件夹 / 音频文件图标（次级墨色）+ 文件名 + 路径（弱文字） |
| 分享 / 在线结果 | 无描边 Card；标题 w500，副标题 caption 弱文字；右侧「加入书架 / 播放」 |

**顶栏为什么不再放「搜索」二字 + 独立输入框 + 搜索按钮**：三件套占掉两行高度，
用户在 AppBar 位置就已经能看到输入框时，标题是纯重复。加载态由搜索按钮位置
的转圈承载（走强调色，跟随墨色主色会是一片灰）。

### 5.10 网盘浏览页版式

自上而下：**网盘切换 → 分享链接卡（可展开）→ 面包屑 → 工具行 → 文件列表 → 底部动作条**。

| 段 | 规格 |
|---|---|
| 文件行 | 44×44 圆角方块 icon：目录 = 次级墨色底 + 主墨色图标；音频 = 强调色底；其它 = 容器中性底 |
| 文本 | 文件名 `body`（主墨色，最多 2 行）；副标题 caption（弱文字，`N 个文件` / 大小） |
| 底部 | 「播放此文件夹全部音频」改为**常驻底部动作条**（墨色实底 + 圆角 12），不再用右下角 FAB |
| 错误态 | 图标与文案走 `AppInk.warning`（此前用强调色的绿图标配「加载失败」，语义反了） |

## 8. 无障碍（WCAG AA）

**文字对比度一律 ≥ 4.5:1。** 规范里所有文字色都实测过，且由 `test/design_system_test.dart`
中的守卫测试锁住 —— 改色板前先跑它。

| 用途 | 浅色（底 `#FAFAF8`） | 深色（底 `#141414`） |
|---|---|---|
| 主文字 | `#1A1A1A` → **16.65:1** | `#EDEDED` → **15.74:1** |
| 次文字 | `#5C5C5C` → **6.38:1** | `#A0A0A0` → **7.04:1** |
| 弱文字 | `#6F6F6F` → **4.81:1** | `#8C8C8C` → **5.48:1** |
| 强调色 | `#1F6F4A` → **5.86:1** | `#52B584` → **7.28:1** |

**初版犯过的错（引以为戒）**：

- 弱文字原本用 `#9E9E9E`，在纸白底上只有 **2.56:1** —— 而它大量用在 11px 的 `micro`
  文本上。小字号恰恰是最不能牺牲对比度的地方。
- 深色模式弱文字原本 `#707070`，只有 **3.72:1**。
- 强调色原本深浅都用 `#1F6F4A`，深色底上仅 **3.01:1**。

生成封面（米白 `#F2EDE4`）：

| 出版色 | 书名 | 作者行（95% 不透明） |
|---|---|---|
| 墨绿 / 藏蓝 / 绛紫 / 煤灰 | 10.15 ~ 12.13 | 7.38 ~ 8.65 |
| 砖红 / 铜褐 / 松绿 | 6.79 ~ 8.03 | 5.21 ~ 5.96 |
| **赭石** | 5.03 | **4.74**（临界，见下） |

> 赭石是 8 色里对比度最低的。作者行原本用 82% 不透明度时只有 **3.98:1**（不达标），
> 已上调到 **95%**。若将来加深赭石或替换该色，必须重跑守卫测试。

其他无障碍约定：

- **触控目标 ≥ 44px**。播放页主控件一行：切章 44、±秒圆钮 46、播放 62；紧凑入口高 34
  但相邻间距充足。改动这些尺寸前先看 §5.6 的宽度预算。
- **动效尊重系统设置**：`AppMotion.reduceMotionOf` 已接入 `MediaQuery.disableAnimationsOf`，
  并支持用户手动开启「减弱动效」。
- 字阶只用 400/500 是为了**可读性稳定**，不是审美偏好：过多的字重会让层级靠"加粗"表达，
  在小字号上反而糊成一团。
