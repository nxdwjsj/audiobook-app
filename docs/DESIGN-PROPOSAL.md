# 聆云 视觉重设计方案书

> 制定：2026-09-24 ｜ 版本：v1.0（待选方向）
> 前置阅读：`DESIGN-SYSTEM.md`（现行规范，本方案是对它的**结构性升级**，不是替代它的令牌体系）

---

## 0. 为什么前几批"看不出差别"（自省）

前四批改的是**表面参数**：页面底色、字重、圆角、封面渲染。这些是"调参"，不是"重设计"。

一个应用让人觉得「换了个软件」，取决于四件事里的至少一件：

| 维度 | 前几批动了吗 |
|---|---|
| **签名视觉元素**（截图一眼能认出的东西） | ❌ 没有 |
| **空间模型**（信息怎么排、怎么滚） | ❌ 没有 |
| **导航结构**（怎么在页面间移动） | ❌ 没有 |
| **动效性格**（怎么动、什么节奏） | ❌ 没有 |

参数调到极致，也只是"同一个软件的精致版"。**本方案要动的是上面四行。**

---

## 1. 方向 A —「有声杂志」Editorial

**一句话**：把这个 App 当成一本**杂志**来排版。每本书是一个封面故事，不是一个列表项。

### 签名视觉元素（截图一眼可辨）
- **竖排中文书名**：书名竖排在封面左侧，配极细竖线 —— 中文竖排天然带"出版物"气质，且和横排的 UI 文字形成强对比。
- **编号感**：书封右上角有 `NO.07` 这样的期号（按入架顺序），呼应杂志期数。
- **实体书的光影**：封面不是平铺的色块，而是带**极细描边 + 一点点纸边投影**，像一本放在桌上的书。
- **大留白 + 极细分隔线**：页面留白率目标 ≥ 40%。

### 空间模型
```
┌─────────────────────┐
│  我的书架     🔍  ⋯ │  ← 顶栏极简，只有搜索与更多
├─────────────────────┤
│                     │
│   ┌───────────┐     │  ← 「本期主打」：当前在听的书
│   │           │     │     封面占屏高约 45%，左侧竖排书名
│   │   封面    │ 竖  │
│   │           │ 排  │
│   └───────────┘     │
│   NO.07             │
│   蛊真人 · 老宝玉    │
│   ▶ 继续收听 第37章  │
├─────────────────────┤
│ 继续收听  ─────────→ │  ← 栏目：横向滚动，一屏露出 2.5 张
│ [卡][卡][卡]         │
├─────────────────────┤
│ 新入库    ─────────→ │
│ [卡][卡][卡]         │
└─────────────────────┘
```

### 导航结构
- 底部 3 个 tab（书架/历史/统计）改为**顶部横向栏目**：`在听 / 书架 / 历史 / 统计`，左右滑动切换。
- 腾出来的底部空间给**常驻迷你播放条**（现在悬浮球是漂着的，改成贴底条更稳、更好点）。
- 进书：点击封面**直接开始播**（不先进详情页），长按才进详情 —— 这是最大的效率改动。

### 动效性格
- 滚动时主打封面 `parallax`：上滚时封面缓慢放大（0.92→1.0），像杂志翻页。
- 栏目横滑时内容整体横向推入，带轻微过冲。
- 播放开始时，主打卡从"静态封面"过渡为"封面 + 环形进度"。

### 效率取舍
| 提升 | 代价 |
|---|---|
| 打开即"继续听"，零点击开播 | 留白多，一屏看到的书少 |
| 横滑栏目代替纵向长滚 | 找特定书要靠搜索 |
| 迷你播放条常驻，随时可控 | 需要适应新的顶部栏目导航 |

**适合**：想要"高级、有格调、一眼认得出"，同时不牺牲日常效率。**与现行「封面为王」基调连续。**

## 2. 方向 B —「播放台」Deck

**一句话**：**这不是一个书架，是一台播放设备。** 打开就是"正在听"。

### 签名视觉元素（截图一眼可辨）
- **深墨底 + 单一荧光强调色**：底色近黑（`#0E0E10`），唯一彩色是酸绿 `#C8F560`，用于进度与当前章节。
- **等宽数字**：时间、章节号、百分比用等宽字体（`Roboto Mono`），像仪表盘读数。
- **环形进度**：主界面是一个大圆环，进度沿环走，封面在圆心（圆形裁切）。
- **黑胶语汇**（可选）：未播放时圆心是黑胶纹理，播放时缓慢旋转。

### 空间模型
```
┌─────────────────────┐
│        蛊真人        │
│     老宝玉 演播      │
│                     │
│      ╭───────╮      │  ← 大圆环：进度沿环走
│     ╱  ┌───┐  ╲     │     圆心是封面（圆形）
│    │   │封面│   │    │
│     ╲  └───┘  ╱     │
│      ╰───────╯      │
│                     │
│   12:34      17:26  │  ← 等宽数字
│   ═══════◉═══════   │
│  ⏮  ⏪15  ⏯  ⏩30  ⏭ │
│                     │
│ ╭─ 倍速1.0x ─ 定时 ─ 章节 ─╮│
│                     │
│   ↑ 上滑打开书架      │
└─────────────────────┘
```

### 导航结构
- **首页 = 播放台**。书架不再是首页，改为**上滑抽屉**。
- 手势为主：上滑书架、左右滑切章、双击暂停。
- 三个栏目（书架/历史/统计）收进抽屉顶部的分段控件。

### 动效性格
- 播放中圆环缓慢旋转（黑胶感）；暂停即停。
- 切章时环形进度"回绕"动画（从满圈倒回零点）。
- 开屏时圆环从中心扩散展开。

### 效率取舍
| 提升 | 代价 |
|---|---|
| 开屏即续播面板，播放相关操作零层级 | **找书多一步**（需上滑抽屉） |
| 倍速/定时/章节同面板，不跳页 | 新用户需要学习手势 |
| 深色夜间友好 | 白天户外可读性略降 |

**适合**：想要"冲击力最强、最有创意、最像换了个软件"。**但会牺牲"找书"这一步的效率。**

## 3. 方向 C —「动态染色」Chromatic

**一句话**：界面的颜色**跟着当前那本书的封面走**。

### 签名视觉元素
- 进入播放页/详情页时，从封面提取主色，实时生成整套界面色（背景、进度条、强调色）。
- 封面是墨绿，整个播放页就是墨绿调；换一本书，整个界面换一套色。

### 空间模型 / 导航
- **不改结构**（保留现有底部 3 tab 与页面布局）。
- 改动量最小，但"每本书一个世界"的感知很强。

### 动效性格
- 切书时全界面颜色**渐变过渡**（约 400ms），像换了一套灯光。

**适合**：想要明显变化但不愿承担结构改动的风险。**创意度中等，风险最低。**

---

## 4. 三方向对比

| | A 有声杂志 | B 播放台 | C 动态染色 |
|---|---|---|---|
| "换了个软件"的感觉 | 强 | **最强** | 中 |
| 创意度 | 强 | **最强** | 中 |
| 日常效率 | **提升** | 播放提升 / 找书下降 | 不变 |
| 改动量 | 大（首页+导航重构） | **最大**（首页=播放器） | **最小** |
| 与「封面为王」基调 | 连续 | 转折 | 连续 |
| 白天可读性 | 好 | 一般 | 好 |
| 风险 | 中 | 高 | 低 |

---

## 5. 我的建议

**选 A 作为主线，把 C 作为 A 的一部分顺带做掉**（A 的栏目里本来就需要"封面色进入界面"来强化杂志感，成本很低）。

**B 我建议先不做**，或者做成"可选皮肤"：它最有冲击力，但把"找书"从一步变两步 —— 而找书是听书 App 的高频动作。为了视觉冲击牺牲高频效率，我不推荐作为默认。

如果一定要"最像换了个软件"，那就直接上 B，但要接受上面那个代价。

---

## 6. 落地方式（选定方向后）

1. **先出一个"可点原型"**（单页 HTML），把首屏与播放页做出来，你在手机浏览器里点着看 —— 比看静态图准得多。
2. 你确认观感后，再按原型改 Flutter 代码，一次改透一个屏幕，每个版本可安装。
3. 每批仍走既定交付流程（验证 → 升版本 → 出包 → 推送 → Release）。

> 这样做的好处：**避免又出现"改完发现不是想要的"** —— 前三批的教训就是没先给你看原型就动手写代码。
